## Fase 4 — Você editar o modelo oficial pelo site *(pequena/média)*

Hoje a curadoria só acontece pelo Table Editor do Supabase.

**SQL** (`supabase-evolucao.sql`, seção 4):
```sql
create table public.admins (
  user_id uuid primary key references auth.users(id) on delete cascade
);
alter table public.admins enable row level security;
create policy "admins: ver o meu" on public.admins for select
  using (user_id = (select auth.uid()));

-- policy ADICIONAL (não substitui nenhuma): admin escreve nas linhas do modelo
create policy "temas: admin edita o modelo" on public.temas for all
  using      (user_id is null and exists (select 1 from public.admins a where a.user_id = (select auth.uid())))
  with check (user_id is null and exists (select 1 from public.admins a where a.user_id = (select auth.uid())));
-- idem para itens

insert into public.admins (user_id) select id from auth.users where email = '<SEU EMAIL>';
```

- Cliente: `souAdmin` vem de `GET admins?select=user_id&user_id=eq.<uid>` na carga.
- Um botão **🛠 modelo oficial** na barra da home liga `modoModelo`, que faz
  `carregarTrilha()` (l.~430) usar o filtro `user_id=is.null` mesmo logado.
- `podeEditar()` vira `logado() && (!modoModelo || souAdmin)`.
- Faixa de aviso bem visível no modo modelo: *"editando a trilha oficial — afeta quem criar
  conta a partir de agora"*. Sem isso é fácil editar o modelo achando que é a sua trilha.

## Fase 5 — Puxar novidades do modelo *(a maior, e a que conserta uma limitação real)*

Hoje o trigger copia o modelo **uma única vez**, no cadastro. Se a trilha oficial melhorar
amanhã, quem já tem conta nunca fica sabendo. É o único item da lista que conserta um
defeito de verdade; o resto é melhoria.

**SQL** (seção 5):
```sql
alter table public.temas add column origem_id uuid references public.temas(id) on delete set null;
alter table public.itens add column origem_id uuid references public.itens(id) on delete set null;

create table public.modelo_dispensado (
  user_id   uuid not null default auth.uid() references auth.users(id) on delete cascade,
  origem_id uuid not null,
  primary key (user_id, origem_id)
);
-- RLS: tudo com user_id = auth.uid()
```

- **Preencher o `origem_id` das cópias que já existem** casando por `slug` (temas) e por
  (tema de origem + `texto`) nos itens — o mesmo truque de casar por texto usado duas vezes
  neste projeto.
- Atualizar `criar_trilha_do_usuario()` para gravar `origem_id` ao copiar.
- Cliente: `carregarNovidades()` compara os ids do modelo com o conjunto dos meus
  `origem_id`, menos os dispensados. Cobre **dois casos**: tema inteiro novo, e item novo
  dentro de um tema que já tenho.
- Faixa na home quando houver novidade → tela `#novidades` com checkboxes,
  **Adicionar selecionados** / **Dispensar**.
- Dispensar grava em `modelo_dispensado`. É isso que impede um tema apagado de propósito de
  reaparecer para sempre.

## Fase 7 — Instalar no celular (PWA) *(pequena)*

- **`manifest.json`** — `name`, `short_name`, `start_url:"./"`, `scope:"./"`,
  `display:"standalone"`, `theme_color:"#FF8A5B"`, `background_color:"#0E1518"`, ícones.
  O `./` é obrigatório: o site vive em `/Estudo-Geral/`, não na raiz do domínio.
- **Ícones 192 e 512 px** — gerar localmente com PowerShell + `System.Drawing` (ele está no
  Windows), sobre o laranja de destaque do app.
- **`sw.js`** — conforme a decisão dele:
  - *network-first* para o documento → uma versão nova entra na hora, sem "por que meu app
    não atualizou?"
  - *cache-first* para ícones e manifest
  - **nunca** interceptar chamadas a `supabase.co` — dado sempre da rede
- Registrar o service worker só sob `https:` — sob `file://` ele não funciona e o duplo
  clique tem que continuar valendo.
- `<link rel="manifest">`, `<meta name="theme-color">` e `apple-touch-icon` no `<head>`.

## Riscos

- **Fase 4/5 mexem em policy e schema em produção.** Exportar antes; rodar o SQL e o push em
  seguida, como foi feito na migração de contas.
- **Fase 5 altera o trigger de cadastro.** Se ele quebrar, o cadastro inteiro falha —
  testar com uma conta descartável antes de qualquer divulgação.
- **Service worker é a coisa mais fácil de errar da lista:** um cache mal configurado serve
  HTML velho e a pessoa jura que o deploy não subiu. Daí o network-first no documento.
